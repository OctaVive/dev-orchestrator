## What this milestone does

This recommended addition provides header/URL/browser preflight report and admin compatibility approval. It extends the phase outcome: a user opens an allowed application while keeping the portal sidebar, or receives a protected new-tab fallback when embedding is incompatible.

The deliverable is **Header/URL/browser preflight report and admin compatibility approval**. The observable completion condition is: xFO/CSP conflicts reported without modification; static checks not claimed sufficient.

## Technical behavior and failure handling

Validate identity, role, context and expiry before changing protected state. Bind secret material to authenticated context, persist state changes atomically where applicable, and expose references or sanitized results to callers.

Deny expired, replayed or wrong-context inputs. Service or key failure must not bypass authentication; committed revocation must remain effective during retries.

Phase-wide boundary: Portal and application origins remain separate. Platform cookies are stripped upstream; incompatible frame policies are reported rather than removed. Authorization failure denies requests and expires stream leases.

These are explanatory design constraints. Do not infer new endpoint names, database tables or infrastructure permissions from the drawings; implementation must follow the authoritative contracts below.
